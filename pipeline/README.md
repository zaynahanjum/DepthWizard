# Terrain Processing Pipeline

## 1. Overview

The terrain processing pipeline is responsible for preparing Digital Terrain Model (DTM) data for the DepthWizard project.

It takes:
- A georeferenced satellite image (GeoTIFF).
- A corresponding Digital Terrain Model (DTM), automatically downloaded from OpenTopography.

The pipeline automatically determines the satellite image's geographic coverage, downloads the corresponding GEDTM30 terrain data, and processes the DTM to match the satellite image's coordinate reference system, spatial resolution, dimensions, and pixel alignment.

The resulting terrain raster can later be integrated with the object information generated by Part A.

## 2. Pipeline Files

| File | Purpose |
|---|---|
| `__init__.py` | Marks the pipeline directory as a Python package, allowing its modules to be imported. |
| `inspect.py` | Inspects the satellite image and DTM, including dimensions, CRS, bounds, resolution, and raster metadata. |
| `check_location.py` | Converts the satellite image's geographic bounds into latitude and longitude coordinates. |
| `check_dtm.py` | Examines DTM metadata, including CRS, dimensions, resolution, NoData values, and elevation statistics. |
| `fetch_dtm.py` | Automatically calculates the satellite image's geographic bounds, downloads the corresponding GEDTM30 data from OpenTopography, and invokes the terrain alignment function. |
| `terrain.py` | Reprojects and resamples a DTM to match the satellite image's spatial grid, then saves the aligned terrain raster. |
| `validate_terrain.py` | Checks whether the generated terrain raster matches the satellite image's CRS, dimensions, transform, bounds, and resolution. |
| `visualize_terrain.py` | Displays the satellite image and aligned terrain elevation raster for visual inspection. |

## 3. Processing Workflow

The automated terrain processing workflow consists of the following steps:

1. Read the georeferenced satellite image.
2. Calculate the satellite image's geographic coverage.
3. Send the geographic bounds to the OpenTopography API.
4. Automatically download the corresponding GEDTM30 terrain data.
5. Save the downloaded DTM as `data/downloads/fetched_dtm.tif`.
6. Reproject the DTM into the satellite image's coordinate reference system.
7. Resample the DTM using bilinear interpolation.
8. Align the DTM to the satellite image's exact raster grid.
9. Save the aligned terrain raster.
10. Validate the spatial alignment.
11. Visualize the satellite image and terrain elevation data.

The downloading and alignment stages are connected, allowing the complete process to run using a single command.

## 4. Input Data

Current sample files:

| File | Description |
|---|---|
| `data/samples/satellite.tif` | Georeferenced RGB satellite image. |
| `data/samples/original_dtm.tif` | Original downloaded Digital Terrain Model retained as a sample/reference dataset. |

The automatic downloader uses the satellite image's geographic bounds to retrieve the corresponding terrain data from OpenTopography.

## 5. Output Data

| File | Description |
|---|---|
| `data/downloads/fetched_dtm.tif` | Automatically downloaded original GEDTM30 terrain data from OpenTopography. |
| `outputs/terrain_dem.tif` | Reprojected and resampled terrain elevation raster aligned with the satellite image. |

The aligned output raster matches the satellite image's:

- Coordinate Reference System (CRS).
- Width and height.
- Spatial transform.
- Geographic bounds.
- Pixel resolution.

The original downloaded DTM is preserved separately from the aligned output.

**Note:** Resampling the approximately 30 m source DTM onto a 10 m grid does not create new 10 m terrain detail. It changes the output grid spacing through interpolation without increasing the original terrain data's spatial detail.

## 7. Running the Scripts

Run commands from the root `DepthWizard` directory with the `depthwizard` Conda environment activated.

### Activate the environment

```bash
conda activate depthwizard
```

### Inspect the satellite image and DTM

```bash
python -m pipeline.inspect
```

### Check geographic bounds

```bash
python -m pipeline.check_location
```

### Inspect the original DTM

```bash
python -m pipeline.check_dtm
```

### Run the complete automatic terrain pipeline

```bash
python -m pipeline.fetch_dtm
```

This single command:

1. Calculates the satellite image's geographic bounds.
2. Downloads the corresponding GEDTM30 terrain data from OpenTopography.
3. Saves the downloaded DTM.
4. Automatically calls the terrain alignment function.
5. Generates the aligned terrain raster at `outputs/terrain_dem.tif`.

An OpenTopography API key must be available through the `OPENTOPOGRAPHY_API_KEY` environment variable.

### Run terrain alignment separately

```bash
python -m pipeline.terrain
```

This command uses the original sample DTM and is useful for independently testing the alignment process.

### Validate the output

```bash
python -m pipeline.validate_terrain
```

### Visualize the satellite image and terrain

```bash
python -m pipeline.visualize_terrain
```

## 8. Future Integration

The aligned terrain raster will eventually be combined with the object information produced by Part A.

The intended integration is:

**Object top elevation = Ground elevation + Object height above ground**

The terrain raster provides the ground elevation, while Part A provides information about objects such as buildings, trees, vegetation, and other detected features.

The combined terrain and object information will eventually be used in the 3D visualization stage of DepthWizard.

Backend integration and 3D scene generation are planned for a later development stage.
